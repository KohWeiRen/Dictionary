# Dictionary Bot — Telegram vocabulary and Spanish practice

Daily useful English vocabulary, AI-generated conversational Spanish lessons,
and Spanish conversation practice with text and voice notes in Telegram.
Python calls cloud APIs; it does not run a language model locally.

## Deploy on your existing GitHub Actions + Render stack

Follow [deploy/CLOUD_SETUP.md](deploy/CLOUD_SETUP.md) for the exact setup.
Add `GEMINI_API_KEY` and the **same `DATABASE_URL`** to GitHub Actions secrets
and your existing Render service. Render also needs `REQUIRE_DATABASE=true`.
Keep the existing Telegram webhook URL and secret, deploy the updated revision,
then use `/lesson`, `/answer` and Spanish text/voice replies in Telegram.
No Pi migration is required.

The existing deployment was verified on 7 October 2026: GitHub Actions runs
`get_random_word_daily.py` on a schedule, and Telegram's live webhook points to
`dictionary-7qig.onrender.com` (Render, not Vercel). Recent scheduled GitHub runs
succeeded. The workflow targets 06:00 Singapore time, though actual runs can be
delayed. These checks did not change the live webhook or send messages.

The new AI features use shared PostgreSQL whenever `DATABASE_URL` is configured.
This preserves lessons, levels, conversation, request counts, generation locks,
daily delivery and Telegram update records across disposable GitHub runners and
Render restarts. The bot initializes tables automatically. Missing cloud storage
produces a clear setup error; it never silently falls back to local SQLite on
Render or in the daily workflow. Neon Free is a suitable starting option; another
PostgreSQL provider also works. Use a dedicated database and a pooled URL.
Audio is synthesized in memory and cached temporarily; losing that cache does
not lose lesson history. SQLite remains available for local development or a Pi
when shared cloud storage is explicitly disabled.

For Pi deployment, run the polling bot and systemd timer below with the same
local data directory. Disable the GitHub schedule only when the Pi timer is
actually enabled. Polling changes Telegram's webhook configuration, so do not
start it merely to test a bot that should remain on Render.

The checked-in GitHub daily schedule is preserved. The Pi services are optional
templates, not an indication that a Pi has already been deployed.

Platform details: [Render free service storage and sleep](https://render.com/docs/free),
[Vercel filesystem limits](https://vercel.com/docs/functions/runtimes), and
[GitHub scheduled workflow caveats](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## What changed

- English selection uses a curated catalogue of 56 useful, less familiar words
  with an everyday meaning, common phrase, two natural examples and a tone note.
  Today's word is stable and repeats only after the catalogue is exhausted.
  Merriam-Webster provides optional dictionary pronunciation and audio.
- Spanish lessons are generated by Gemini, not taken from a fixed lesson bank.
  Each daily lesson has 2–3 useful words/chunks, one grammar pattern, a short
  translated dialogue, a common mistake, an exercise and a model answer.
- The AI sees recent lessons and practice, so it can reuse learned vocabulary,
  vary situations and respond to mistakes. A1 foundation prompts guide early
  progression; after those, the AI chooses the next pattern from your level and
  history. `/level` changes your level; the bot does not claim to measure mastery.
- `/practice` starts a role-play. Spanish text and voice replies receive grammar
  corrections, English explanations and a follow-up question. Voice replies also
  show what the model heard; the transcript may need correcting if audio is unclear.
- Normal and slow sentence MP3s play directly in Telegram and are cached on disk.
  Spanish dictionary URLs now use `/es/me/` and English uses `/en/us/`.
  Spanish lookups filter `meta.lang=es` to avoid English entries in the bilingual API.
- PostgreSQL stores lessons, levels, recent conversation and an AI request counter.
  Replaying a saved lesson does not use another AI request. Concurrent daily
  requests share a generation lock. Failed generation does not save a broken lesson.
  Completed daily posts and repeated Telegram update IDs are also recorded to
  prevent ordinary reruns from duplicating work.

## Free AI setup

Get a Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey).
The default model is `gemini-3.8-flash`, verified against Google's current
[model list](https://ai.google.dev/gemini-api/docs/models) and
[free-tier pricing](https://ai.google.dev/gemini-api/docs/pricing).
Use a free-tier project if you want free usage. The code cannot verify your
billing tier; a key linked to a paid project can incur charges.
Free API use is subject to your project's quota, visible in AI Studio; there is
no promise of unlimited free use. The bot defaults to a global cap of 20 AI
requests per Singapore day across lessons, text and voice practice. Set
`AI_DAILY_LIMIT` lower if your free quota is smaller. Cached lessons and dictionary
lookups remain available after the cap is reached. Provider quota errors are
reported clearly and aren't automatically retried.

Requests use Google's current [Interactions API](https://ai.google.dev/gemini-api/docs/interactions-overview)
with JSON-schema output and local Pydantic validation, through existing `httpx`.
No separate AI SDK is needed. A new lesson or conversation reply usually uses
one API request. If a model is overloaded, times out, cannot be found, or returns
an invalid lesson, the bot tries the next model: `gemini-3.8-flash` →
`gemini-3.7-flash` → `gemini-3.6-flash`. These models currently have free-tier
pricing. It makes at most one attempt per model and three attempts per generation;
every attempt counts against `AI_DAILY_LIMIT`. HTTP 200 alone is insufficient:
the response must also finish and pass local schema validation. Authentication,
invalid-request and provider quota errors stop immediately.

Fallback works without extra configuration. Optionally set
`GEMINI_FALLBACK_MODELS=gemini-3.7-flash,gemini-3.6-flash` on both hosts to choose
the order, or `none` to disable it. Fallback entries must be among the three
verified models above; `GEMINI_MODEL` remains your chosen primary model.
`gemini_failure` and `gemini_fallback_success` logs share a reference ID and show
the attempted/successful model. Grammar content is generated,
so structural validation is not a guarantee of linguistic accuracy.

Spanish sentence audio uses [gTTS](https://gtts.readthedocs.io/), which needs no
additional API key. It uses Google Translate speech synthesis and can become
unavailable; the lesson text remains accessible and `/listen` retries audio.
It defaults to Mexican Spanish (`SPANISH_TTS_TLD=com.mx`). For Spain use `es`.

Lesson context, practice text and voice notes go to Google for AI processing.
Free-tier content may be used to improve Google's products. `store=false` avoids
server-side Interactions conversation storage; it does not override the provider's
free-tier data policy. Only transcripts and recent practice are saved locally;
raw voice notes are downloaded in memory and not kept on disk. The bot corrects
spoken grammar from what it hears, but does not give pronunciation scores.

## Install on the Pi

Use Python 3.11+ on Raspberry Pi OS (64-bit recommended).
This section is optional; the existing deployment uses Render. For a Pi with
local SQLite, omit `DATABASE_URL` and set `REQUIRE_DATABASE=false`.
Keep your existing `important_info/.env` and add the Gemini settings. If installing
fresh, copy `important_info/.env.example` to `important_info/.env` and fill in all
credentials. `BOT_OWNER_ID` must be your numeric Telegram chat ID. AI lessons and
practice are restricted to that chat to conserve the personal bot's free quota.

From the checked-out project directory:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python get_random_word_daily.py --check
```

`--check` verifies required settings are present without printing keys, calling
Gemini or sending messages. It does not validate keys remotely.
Required settings:

```env
TELEGRAM_API_KEY=...
BOT_OWNER_ID=...
MERRIAM_WEBSTER_DICT_API=...
MERRIAM_WEBSTER_SPANISH_DICT_API=...
GEMINI_API_KEY=...
GEMINI_MODEL=gemini-3.8-flash
SPANISH_LEVEL=A1
AI_DAILY_LIMIT=20
SPANISH_TTS_TLD=com.mx
```

The defaults keep persistent data in `data/` within the checkout (Git-ignored).
Set `BOT_DATA_DIR` to an absolute path if you want it elsewhere. Preserve this
folder across updates: it contains lesson history, conversation context and audio.
The daily job and interactive bot must use the same `.env` and data directory.

Test AI lesson generation without sending Telegram messages:

```bash
.venv/bin/python get_random_word_daily.py --preview
```

This calls Gemini if today's lesson is not cached and saves the result. With a
missing/invalid key or exhausted quota, it prints a clear status, plus a saved
lesson to review if one exists. To send today's practice and two audio tracks:

```bash
.venv/bin/python get_random_word_daily.py
```

## Interactive Telegram bot on the Pi

```bash
.venv/bin/python run_bot.py
```

This receives messages by long polling. No public IP, tunnel or incoming port is
needed. Run one polling process per Telegram bot. Polling removes an existing
webhook, so choose polling or the original FastAPI webhook, not both.

| Telegram command | Behavior |
| --- | --- |
| `/word` or `/daily` | Today's English word + generated Spanish lesson and audio |
| `/lesson [YYYY-MM-DD]` | Generate/replay today or replay a previously saved date |
| `/answer [YYYY-MM-DD]` | Reveal that saved lesson's model answer |
| `/practice [topic]` | Start a new role-play, e.g. `/practice ordering coffee` |
| `/reply <Spanish>` | Correct your sentence and continue the conversation |
| Spanish text in your private chat | Same as `/reply` |
| Voice note (up to 60 seconds, under 2 MB) | Transcribe, correct grammar and send a spoken follow-up |
| `/listen [Spanish text]` | Normal + slow pronunciation; without text, today's saved dialogue |
| `/level [A1|A2|B1|B2]` | View/change the level (new practice now; new lesson tomorrow) |
| `/reset` | Reset conversation context; preserve lessons |
| `/en <word>` or `/dict <word>` | Original English dictionary lookup |
| `/es <palabra>` | Original Spanish dictionary lookup, with corrected audio |
| `/help` | Commands |

## Run automatically with systemd

Templates are in `deploy/`. Before installation, edit **User**, **WorkingDirectory**
and **ExecStart** to match your Pi account and checkout path. The supplied examples
use user `pi` and `/home/pi/Dictionary`; modern Pi installations can use a different
username. The timer defaults to **06:00 Asia/Singapore**, matching the former daily
workflow's target time. Change `OnCalendar` in the timer to your preferred time.

From your project directory:

```bash
sudo cp deploy/dictionary-bot.service /etc/systemd/system/
sudo cp deploy/dictionary-daily.service /etc/systemd/system/
sudo cp deploy/dictionary-daily.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now dictionary-bot.service dictionary-daily.timer
```

The bot restarts after failures and starts on boot. The timer sends daily practice;
`Persistent=true` catches up after downtime. Don't also schedule the same script
with cron. If switching to Pi delivery, remove the `schedule` trigger from the
GitHub workflow when enabling this timer, so there is only one daily sender.

Useful checks:

```bash
systemctl status dictionary-bot.service
systemctl list-timers dictionary-daily.timer
journalctl -u dictionary-bot.service -n 50
journalctl -u dictionary-daily.service -n 50
```

After pulling an update and installing changed dependencies, restart the bot:

```bash
.venv/bin/python -m pip install -r requirements.txt
sudo systemctl restart dictionary-bot.service
```

The one-shot daily job loads current code on its next run. If you change a unit
file, copy it again and run `sudo systemctl daemon-reload`.

## Original webhook mode

If you prefer your existing webhook host, set `WEBHOOK_SECRET` and run:

```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

Point Telegram at `https://<host>/telegram/<WEBHOOK_SECRET>`. Both runners use
`Custom_modules/bot_commands.py` for the same commands and voice handling.
The GitHub Actions sender needs the existing four Telegram/dictionary secrets
plus `GEMINI_API_KEY`; `GEMINI_MODEL`, `GEMINI_FALLBACK_MODELS` and `SPANISH_LEVEL`
are optional repo variables.
For the existing Render + GitHub setup, configure the same PostgreSQL connection
on both hosts using [the cloud guide](deploy/CLOUD_SETUP.md). The cloud storage
adapter is implemented; a real database URL and Gemini key are needed to activate it.

## Verification and key files

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Tests mock Telegram, Gemini and gTTS. They cover API payloads, secret-safe errors,
quota limits, concurrency, persistent cache/history, voice handling, daily delivery,
English selection, Spanish dictionary direction and pronunciation, and both runners.
A real Gemini generation test requires your own API key; none is configured in
this development checkout. No messages were sent to your Telegram chat during tests.
The **Bot checks** workflow additionally runs the integration scenarios against
real PostgreSQL in a disposable service container. Those cases are skipped locally
unless `TEST_DATABASE_URL` points to a dedicated `dictionary_test` database.
